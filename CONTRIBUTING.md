# Contributing to 3AI Defence Open

## Overview

Thank you for your interest in 3AI Defence.

This repository is the public architecture and documentation surface of a
proprietary cyber-defence project.

It is not the production source repository.

---

## Useful Contributions

Contributions may include:

- documentation corrections
- architectural clarification
- diagram improvements
- terminology corrections
- resilience observations
- privacy observations
- defensive interoperability discussion
- safe implementation-neutral examples
- broken-link reports
- public documentation improvements

---

## Defensive-Only Scope

Contributions must remain defensive.

Do not submit:

- offensive exploitation code
- malware
- credential theft tooling
- persistence tooling
- destructive payloads
- instructions for unauthorized access
- real incident data
- private infrastructure details
- bypass procedures for production defenses

---

## Before a Large Contribution

For substantial proposals, please discuss the idea before investing significant
effort.

This is especially important for changes involving:

- architecture
- module responsibilities
- security boundaries
- AI orchestration
- resilience
- containment
- recovery
- external integrations
- intellectual property

---

## Public / Private Boundary

Contributions should follow the project principle:

> **Document the architecture, preserve the defensive boundary, protect the implementation.**

Public contributions should focus on:

- architecture
- concepts
- interfaces
- diagrams
- safe examples
- documentation

Private production logic remains outside this repository.

---

## Do Not Submit Sensitive Material

Do not submit:

- credentials
- tokens
- private keys
- production configuration
- recovery material
- internal monitoring rules
- private telemetry
- real infrastructure topology
- customer information
- CashOut security configuration
- private incident records
- proprietary partner material

---

## Pull Requests

A useful pull request should:

- have a clear purpose
- remain within defensive scope
- keep terminology consistent
- avoid secrets and private data
- avoid operational attack detail
- preserve public/private boundaries
- update related documentation where necessary

---

## Documentation Style

Prefer documentation that is:

- technically precise
- implementation-neutral where details are sensitive
- explicit about current capability versus architectural direction
- clear about trust boundaries
- clear about authorization
- clear about module responsibility
- understandable without private implementation access

---

## Intellectual Property

Do not contribute material you do not own or have permission to submit.

By submitting a contribution, you represent that you have the necessary rights
to do so and grant the project owner permission to use, reproduce, modify,
distribute and sublicense the contribution as part of 3AI Defence, subject to
applicable law.

Substantial or commercially significant contributions may require separate
written terms before acceptance.

Submission of a contribution does not grant rights to:

- private 3AI Defence source code
- proprietary defensive logic
- trademarks
- patents
- private datasets
- CashOut implementation
- Outy private implementation
- confidential integrations

See [Intellectual Property](INTELLECTUAL_PROPERTY.md).

---

## Security Issues

Do not publish exploitable security issues through a normal pull request.

See [Security Policy](SECURITY.md).

---

## Third-Party Material

Third-party code, datasets, names, APIs and services remain subject to their own
licenses and terms.

Do not copy third-party proprietary material into this repository without
authorization.

---

## Acceptance

Contributions may be accepted, modified or declined according to:

- architecture
- defensive scope
- security
- product direction
- intellectual-property boundaries
- project requirements

Thank you for helping improve the public technical surface of 3AI Defence.
